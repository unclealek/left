# Settings and regional preferences — 2026-10-20

## Implemented locally

- Settings now includes App language, Measurement units, Privacy preferences, Hidden & muted venues, Download my data, Licences, and the installed native version/build. The existing identity-removal flow is presented as a request for account deletion with retained-record wording; its processing/authentication behavior is preserved.
- Device preferences are versioned in AsyncStorage. Language and units default to following the device, with explicit overrides. The user-confirmed launch languages are English, Finnish and Swedish. Unsupported languages and uncatalogued copy fall back to English. Language changes propagate through the root without intentionally clearing navigation or onboarding state.
- App-owned interface copy uses source-keyed catalogs, including main onboarding/auth, Home, Profile, settings, safety and venue screens. Preset interest values remain stable in storage and are translated for display. Names, gathering descriptions, venue data, legal website content and licence text are not machine-translated. Native OS/provider prompts follow their own language settings. Catalog translations need native-speaker review; unconverted dynamic/server messages can still appear in English. This is an initial supported-language implementation, not a claim that every possible message or external surface is translated.
- All live distance presentation paths on Home, venue detail, map preview and venue selection use one formatter. Stored metres and proximity/security thresholds are unchanged. Metric displays metres/kilometres; imperial displays feet/miles. Regional number formatting and independently selectable device units are respected. Gathering date displays use the chosen app locale; venue chart weekday keys/timezone calculations retain canonical English keys while labels/summaries are translated. Currency amounts remain denominated in their actual currency; no exchange-rate conversion is introduced.
- Usage analytics/diagnostics are off by default. The PostHog SDK is not constructed until a saved opt-in is loaded. Runtime opt-in/out and event/log guards implement the switch, and account identity resets reapply the chosen preference. Language/unit/analytics preferences explicitly apply on this device and do not sync across devices.
- Settings’ Hidden & muted venues entry opens the existing venue privacy screen. It lists hidden/muted venues and uses the existing Unhide/Unmute actions. The mistakenly added people-management list, its client helpers and its proposed `list_my_blocks()` RPC were removed following the user’s clarification. Existing person-block/report safety actions elsewhere are unchanged. Venue controls require no new migration.

- Data download creates a JSON copy of account-owned app database records, then opens the native share sheet to let the user choose Files or another destination (web uses a browser download). It paginates each category, fails rather than sharing an incomplete result, rechecks account identity, and removes its temporary native cache file after the share sheet finishes. It includes basic auth account identifiers, profile, presence/prompts, outgoing approaches/waves, own contact choices, own submitted reports/removal requests, saved places, own hosted/joined gatherings, venue preferences, legal acknowledgements, hidden/blocked relationships, own social events and safety zones. Provider-held analytics, backups, internal safety reviews and other people's private records are excluded and identified in the export's scope text. This is an app-record download, not a complete legal access-request response across every processor. Separate category requests are not one immutable database snapshot.
- Licence notices are generated from locally installed production dependency metadata and available licence/NOTICE files with `node scripts/generate-licences.mjs`. The virtualized viewer lists 764 unique package/version notices. 91 packages have no bundled licence file and show that limitation plus upstream repository metadata; this inventory does not replace a native SDK/font attribution audit before release.

## Prepared backend change — not applied

`supabase/migrations/20261020100750_account_settings_tools.sql` adds private privileged implementations and public invoker wrappers for `export_my_data(category, offset)`. Every call requires an authenticated active non-anonymous account. The server derives ownership from `auth.uid()`; clients cannot supply a target account. Export category/table/owner columns come from a fixed allowlist; raw profile access is not granted. Review/admin/failure fields are removed from exported rows. Existing table RLS is unchanged.

**Only data download requires this migration before it works against staging.** Venue hiding/muting reuses the existing implementation. There have been no live migration, schema/data writes, new acceptance records, deployments, pushes, OTA updates or TestFlight uploads for this work. The published legal pages remain drafts and acceptance remains disabled under the default configuration.
